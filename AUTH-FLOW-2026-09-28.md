# 4uStream authentication flow

## Production flow

Signup -> Email Verification -> Active

- New accounts are created with `status: unverified`.
- The verification email is sent by the server-side `/api/send-verification` route.
- Unverified accounts cannot read protected streaming content because Firestore rules require both `email_verified == true` and `status == active`.
- When the verification link is opened while the user is signed in, `/auth-action` refreshes Firebase Auth and activates the profile immediately.
- If the link is opened on another device/browser, the next successful login activates the profile after Firebase confirms the email is verified.
- The account page also provides `I verified my email` and `Resend email` actions.
- Existing legacy `pending` profiles can be promoted to `active` only after email verification; no new account uses `pending`.
- Admin approval is not part of signup.

## Security notes

- `auth-users.json` is excluded from the project because credential-like data must not be committed.
- `tsconfig.tsbuildinfo` is excluded as generated build state.
- Client users cannot self-assign VIP or change their own status to disabled/active except the controlled verified transition from `unverified` (or legacy `pending`) to `active`.
